# Speculative sampling

Это общий алгоритм, а не описание жадного бенчмарка из прогона. Про него см.
[greedy-проверку](verification.md).

Пусть $Q_j$ это распределение, из которого draft реально предлагает токен, а $P_j$
распределение target при используемых настройках сэмплирования. Для предложения
$d_j \sim Q_j$:

$$
\alpha_j =
\min\left(1, \frac{P_j(d_j)}{Q_j(d_j)}\right).
$$

Токен принимается с вероятностью $\alpha_j$. При отказе корректирующее
распределение:

$$
R_j(v)
=
\frac{\max\left(P_j(v) - Q_j(v), 0\right)}
{\sum_u \max\left(P_j(u) - Q_j(u), 0\right)} .
$$

У кандидата, который предложить нельзя, $Q_j(v) = 0$.

## Что требуют формулы

Распределения должны быть настоящим распределением предложения, вместе с фильтрами:
top-k, top-p, temperature, штрафами за повторы. Не идеализированный softmax,
который никогда не применялся. Если подставить чистое $Q$, а сэмплировать из
отфильтрованного, равенство распределений на выходе ломается, и ошибка остаётся
тихой.

Это условие корректности rejection sampling. Оно не доказывает, что C++
runtime выполняет его во всех режимах. В выполненном сравнении ответы speculative и
no-draft часто различались, и причина пока не найдена. См.
[Чего формулы не говорят](../caveats.md).

Сама схема из
[Fast Inference from Transformers via Speculative Decoding](https://arxiv.org/abs/2211.17192).
