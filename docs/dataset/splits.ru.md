# Сплиты и утечки

Разбиение по семействам должно удовлетворять условию

$$
\mathcal{F}_{\mathrm{train}} \cap \mathcal{F}_{\mathrm{val}}
=
\mathcal{F}_{\mathrm{train}} \cap \mathcal{F}_{\mathrm{test}}
=
\mathcal{F}_{\mathrm{val}} \cap \mathcal{F}_{\mathrm{test}}
=
\varnothing .
$$

Два языковых варианта одного файла не являются независимыми источниками. Как и
вопрос с его пересказом, или документ с его конспектом. Разбиения по строкам JSONL
без учёта семейства недостаточно.

## Почему единица это семейство

Draft имитирует одну замороженную модель на узком распределении задач. Почти
дублирующиеся контексты делают валидацию лучше, чем модель есть: блок можно
предсказать по соседней записи из обучения, и точность отражает запомненные
семейства, а не обобщение на новую задачу.

Отказ тихий. Кривая лосса выглядит нормально, а единственный симптом это бенчмарк,
который не воспроизводит выигрыш с валидации.

## Практическая проверка

- Строить ключ семейства по происхождению контента, а не по имени файла.
- Проверять пустоту трёх пересечений на реальных списках записей, а не на
  задуманной схеме.
- Помнить про единицу счёта: 600 контекстов, разбитых 480/120, это утверждение о
  контекстах, а не о файлах.
