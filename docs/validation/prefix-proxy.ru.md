# Prefix proxy

Prefix proxy считает длину верного начала блока:

$$
J_i^{\mathrm{offline}}
=
\sum_{j=1}^{m}
\prod_{r=1}^{j} c_{i,r} .
$$

Пример:

```text
Верно по позициям: [1, 1, 0, 1, 1, 0, 1]
Accuracy:          5 / 7
Prefix:            2
```

После первой ошибки оставшиеся верные токены prefix не удлиняют. Блок
`[1, 1, 1, 0, 0, 0, 0]` имеет точность ниже, но prefix три.

Среднее по примерам:

$$
\operatorname{PrefixProxy}
=
\frac{1}{B}\sum_i J_i^{\mathrm{offline}} .
$$

## Как читать значение

При $b = 8$ максимум равен семи. Значение 2.621 не означает, что сервер в среднем
принял 2.621 из трёх draft-токенов. Это разные процедуры на разных данных.

При этом proxy остаётся ближайшим offline-аналогом того, что поощряет проверка:
проверка тоже останавливается на первом расхождении. Слабое место в том, что
обратная связь не учитывается. Неверный токен на первой позиции меняет вход для
второй, а teacher-forced proxy этого не видит.
