# Офлайн-обучение EAGLE-3 на V100

llama.cpp целиком загружает Whittle Q5 на V100 с 32 ГБ памяти и по частям
сохраняет [скрытые состояния](whittle-features.md) на диск. После захвата GGUF
Whittle выгружают. SpecForge обучает однослойную draft-модель на сохранённых
признаках с замороженными эмбеддингами токенов и LM head.

## Захват, обучение и экспорт

1. Подготовить JSONL с ID токенов Whittle и маской обучающих позиций. Экспортёр
   читает последовательность частями и сохраняет состояние Whittle между ними.
2. Сохранить каждый пример отдельным файлом SpecForge и разложить файлы по
   шардам. Экспортёр пишет их атомарно. При повторном запуске с тем же
   манифестом он пропускает готовые файлы. Манифест фиксирует файл модели,
   хеш входных данных, бинарник экспортёра и формат признаков.
3. Обучать в FP16 с SDPA, батчем из одного примера и накоплением градиентов за
   четыре шага. Используется gradient checkpointing. FP32-копия весов для AdamW
   хранится на GPU. Сопоставление словарей и расчёт логитов Whittle по частям
   сокращают расход памяти. Словарь draft-модели содержит 32 000 токенов.
   Rollout идёт в три шага.
4. При возобновлении из чекпойнта использовать тот же кэш, порядок примеров
   и настройки накопления градиентов. Готовый чекпойнт экспортировать в FP16
   GGUF с идентификатором формата, затем загрузить в сервер с патчами в режиме
   `draft-eagle3`.

В прогоне использовали патчи Whittle поверх
[llama.cpp 5297534](https://github.com/ggml-org/llama.cpp/commit/52975342ff6b85127ff31930d39e36725fd08809)
и [SpecForge 91d8a5a](https://github.com/sgl-project/SpecForge/commit/91d8a5a5443c5b93a905f8eead79f23a00311a41).
В сборку перенесли вариант Flash Attention для коротких запросов на Volta и
преобразование K-quant/MXFP4.
