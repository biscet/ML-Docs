# Признаки Whittle для EAGLE-3

## Как работает EAGLE-3

EAGLE-3 ускоряет генерацию через спекулятивное декодирование. Маленькая
draft-модель предлагает несколько токенов, а Whittle проверяет их за один
проход. Например, draft предложил `A B C`. Если при жадном декодировании
Whittle подтверждает `A`, а на второй позиции выбирает `D`, в ответ идут
`A D`, а `B C` отбрасываются. См. [greedy-проверку](../runtime/verification.md).

Draft-модель EAGLE-3 предсказывает вероятности токенов напрямую. На первом шаге она
использует признаки нескольких слоёв Whittle и эмбеддинг последнего
известного токена. На следующих шагах в draft-декодер возвращаются его
собственное скрытое состояние и эмбеддинг только что предложенного токена.
При обучении модель тоже делает несколько шагов на собственных скрытых
состояниях. Авторы называют это *training-time test*.
[Статья об EAGLE-3, раздел 3](https://arxiv.org/html/2503.01840v3#S3).

## Какие состояния сохраняет экспортёр

Экспортёр сохраняет входы attention в блоках Whittle Q5 с индексами 2, 20 и 37.
Нумерация начинается с нуля. Перед attention обученный миксер Whittle объединяет
четыре потока hyper-connections в вектор из 2048 значений. Через тот же миксер
проходит вклад n-gram memory.
[Карточка Whittle](https://huggingface.co/whittleOrg/Whittle-Qwen-3.8-35B-A3B).

Пусть $u_p^{(\ell)}$ обозначает вход attention блока $\ell$ на позиции $p$.
Экспортёр соединяет три вектора в порядке блоков.

$$
a_p = \operatorname{concat}(u_p^{(2)}, u_p^{(20)}, u_p^{(37)})
$$

Вектор $a_p$ из 6144 значений сохраняется в `aux_hidden_state`. Затем обучаемый
слой EAGLE-3 проецирует его в размерность draft-модели.

У Whittle 40 блоков. Индекс `40` в экспортёре указывает на выход финального
миксера перед LM head. При обучении LM head по этому вектору вычисляет
распределение вероятностей следующего токена.

## Формат файла

В каждом файле SpecForge хранится одна последовательность из $T$ токенов.

| Поле | Размерность | Тип |
| --- | --- | --- |
| `input_ids` | `[T]` | int64 |
| `loss_mask` | `[T]` | int64, значения 0 или 1 |
| `aux_hidden_state` | `[1, T, 6144]` | FP16 |
| `hidden_state` | `[1, T, 2048]` | FP16 |

Экспортёр и сервер используют один режим извлечения, `qwen4exp` в llama.cpp.
При декодировании draft-модель получает три входа attention в порядке,
указанном в draft GGUF. При загрузке сервер проверяет идентификатор формата
`native-attn-mix-v1`.

Эмбеддинги токенов и LM head для обучения берут из квантизированного GGUF
Whittle и замораживают. Сохранение признаков и перевод LM head в FP16 могут
дать небольшую погрешность округления.

## Сдвиг токенов

На шаге 0 draft-декодер работает на позиции $p$. На вход идут признаки из
строки $p$ после проекции и эмбеддинг токена $x_{p+1}$. Модель предсказывает
$x_{p+2}$. Например, при $p=10$ она получает признаки из строки 10 и токен 11,
чтобы предсказать токен 12.

При обучении на глубине $d$ SpecForge берёт входной токен $x_j$ из датасета.
Распределение $P_j$ для следующего токена $x_{j+1}$ получается из финального
состояния Whittle $h_j$. Здесь $H_{\mathrm{W}}$ обозначает LM head Whittle.

$$
j = p+d+1, \qquad P_j = \operatorname{softmax}(H_{\mathrm{W}}(h_j))
$$

SpecForge сравнивает распределения на словаре draft-модели. Маску читает из
строки $j$. Строки за концом последовательности пропускаются.
[Код расчёта лосса в SpecForge](https://github.com/sgl-project/SpecForge/blob/91d8a5a5443c5b93a905f8eead79f23a00311a41/specforge/algorithms/objectives/protocols/eagle3.py).

Два FP16-тензора занимают $(3 \cdot 2048 + 2048) \cdot 2 = 16{,}384$ байта на
токен. На 100 000 токенов нужно около 1.53 GiB плюс место под ID, маски и
метаданные.

См. [обучение на V100](offline-v100.md).
