# Общая конфигурация обучения

Продолжения и скрытые признаки генерировала Whittle Q5. В ранних опытах её
token IDs служили жёсткими метками. В поздней KL-ветке дополнительно сохраняли
[вероятности по всему словарю](../objective/forward-kl.md).

## Модели

Начальные веса draft взяли из Ornith 1.5 DFlash2. Размеры подходили, но веса
ещё требовалось адаптировать к признакам Whittle.

| Параметр draft | Значение |
| --- | ---: |
| Параметров | 526,251,520 |
| Слоёв / тензоров | 6 / 96 |
| Hidden / intermediate size | 2,048 / 6,144 |
| Attention / KV heads | 32 / 8 |
| Head dimension | 128 |
| Словарь | 248,320 |
| Архитектурный block size | 16 |
| Ранг селектора | 256 |
| Кандидатов на позицию | 16 |

Веса Whittle, embedding токенов и выходная LM head оставались фиксированными.
Embedding и head читались из целевого Q5 GGUF.

## Признаки

Capture извлекал признаки слоёв [1, 6, 11, 16, 22, 27, 32, 37]. В конфигурации
Python-модели индексы были на единицу меньше. Четыре residual streams
hyper-connections усреднялись для каждого выбранного слоя.

Один токен давал восемь векторов по 2,048 значений. После объединения получалось
16,384 признака. Формулы приведены в разделах [захвата признаков](../data/feature-capture.md)
и [проекции](../data/feature-projection.md).

## Anchor и ширина

Anchor задаёт известный токен внутри сохранённого ответа Whittle. Draft получает
предшествующее окно признаков и блок с масками на будущих позициях:

```text
Вход, ширина 4:  [известный anchor, MASK, MASK, MASK]
Прямые метки:    [следующий токен, следующий, следующий]
```

Ширина включает anchor: при ширине 4 получаются три будущие метки, при ширине 8
семь. Архитектурный block size 16 не означает, что каждый шаг предсказывал
16 токенов.

LoRA-пилот использовал до 96 токенов признаков перед anchor, последующие тренеры
использовали окно 384. Capture мог обрабатывать длинный prompt и ответ, но
конкретный backward получал выбранное окно признаков.

## Согласованность данных

Метки токенов, скрытые признаки и мягкие распределения должны соответствовать
одному тексту и одной конфигурации target. После изменения текста старое
выравнивание токенов и признаков использовать нельзя. Длинный capture сам по
себе не увеличивает число позиций с прямым token loss.

Счётчики, используемые в заметках, описаны в [обозначениях](../overview/notation.md).
