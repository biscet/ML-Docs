# Hard CE против forward KL

Обе ветки использовали одну [обучаемую часть partial unfreeze](partial-unfreeze.md)
и начальные веса долгого selector-run, шаг 58,864. Опыт сравнивал жёсткие
метки токенов с [мягкими распределениями по всему словарю](../objective/forward-kl.md).

## Одинаковое начало

| Параметр | Обе ветки |
| --- | --- |
| Запланировано контекстов | 16,384: 8,192 RU, 8,192 EN |
| Batch / окно признаков | 4 / 384 |
| Anchor / microbatch / ширина | 8 / 8 / 4 |
| LR / warmup | 2e-6 / 32 обновления |
| Состояние оптимизатора | Новое |
| Данные, anchor и порядок | Одинаковые |

Первый шард содержал 16 контекстов для проверки полного контура, следующие
по 64. Порог первого сравнения составлял 512 контекстов. На ближайшей границе
шарда обе ветки обработали 528 контекстов, то есть 132 обновления.

## Что означают поля loss

| Поле | Значение |
| --- | --- |
| `ce` | Hard token CE |
| `kl` | Forward KL по всему словарю |
| `selector_ce` | Selector CE |
| `loss` / `unweighted_loss` | Диагностическое CE + 0.5 x selector CE |
| `objective_loss`, CE-ветка | CE + 0.5 x selector CE |
| `objective_loss`, KL-ветка | KL + 0.5 x selector CE |

Поле `loss` в KL-отчёте оставалось диагностикой по hard CE. Оно не было
оптимизируемой KL-функцией.

| Метрика | Начальное состояние опыта | CE, шаг 132 | KL, шаг 52 |

## Продолжение KL

После одинакового бюджета продолжили только KL. Она дошла до шага 660:
2,640 контекстов в 42 шардах. Запланированный проход по 16,384 контекстам
остался незавершённым.

Лучшим экспортом остался шаг 52 после 208 обучающих контекстов. Он вошёл в
v1.2.1. У последнего состояния hard CE и KL были ниже, но prefix составлял
1.648438. [Правило отбора](../workflow/experiment-selection.md) сохранило шаг 52
с prefix 1.664063.

Решение продолжить KL не доказывает её универсального превосходства над CE.
У выбранных состояний в таблице также разное число обновлений.

Исходник в архиве: `experiments/07-ce-kl-partial/scripts/train_chunk.py`.
