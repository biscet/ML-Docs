# Selector-only пилот

Короткий опыт стартовал от v1.2.0 и обучал только три матрицы селектора:

```text
candidate_selector.predecessor_codebook.weight
candidate_selector.successor_codebook.weight
candidate_selector.hidden_projection.weight
```

Это 127,664,128 обучаемых параметров. Остальные 398,587,392 были заморожены.
Фиксированные представления, LM head и backbone сохраняли unary logits и
состав top-16. Селектор мог менять порядок кандидатов, но не добавлять
отсутствующий токен.

## Обучение и проверки

| Параметр | Значение |
| --- | --- |
| Контексты / проходы | 128 / 8 |
| Anchor / ширина / batch | 8 / 4 / 4 |
| Обновления | 256 |
| Прямые предъявления меток | 24,576 |
| LR в конфигурации / фактический начальный | 1e-5 / 2e-4 |
| Objective | 0.5 x selector CE |

Наставник выбрал LR 2e-4 до начала обучения. Token CE оставался диагностикой
и не входил в оптимизируемую функцию. Хеши замороженных GGUF-тензоров сверяли
с родителем; unary CE и top-16 recall не менялись.

## Результат

| Метрика | До | Выбранный шаг 96 | Последний шаг 256 |
| --- | ---: | ---: | ---: |
| Selector CE | 0.871796 | 0.870162 | 0.867392 |
| Self-conditioned accuracy | 61.9141% | 62.2396% | 61.4583% |
| Correct-prefix proxy | 1.689453 | 1.697266 | 1.681641 |

Последний шаг ещё снизил selector CE, но сократил правильный префикс.
Выбрали шаг 96; от него началось [долгое обучение селектора](selector-long.md).

Пилот использовал вдвое больше проходов, чем uniform-опыт. При сравнении
нельзя объяснять всю разницу одной лишь обучаемой частью.

Исходники архива: `experiments/04-selector-only/`.
