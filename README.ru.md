# База знаний по языковым моделям

Заметки про языковые модели: как их обучают, как ускоряют инференс и что на
самом деле показывают замеры. Репозиторий задуман как растущий. Новые темы
получают свою папку в `docs/`, а каждая страница отвечает на один вопрос.

Сейчас в нём один раздел: разбор прогона Stage-2 для DFlash2. Там видно, что
считает тренер, какие формулы применяет, что получилось на выходе и чего эти
числа не доказывают. Исходником была длинная русская заметка. Оригинал лежит в
`original/` без правок, а английская версия разбита на небольшие страницы и
собирается в сайт.

Сайт двуязычный. У каждой страницы есть английский файл и русский двойник, сборка
идёт в `/` и `/ru/`, а в шапке есть переключатель, который остаётся на той же
странице.

Английский README: [README.md](README.md).

## Что уже есть

| Путь | Содержимое |

## Как добавить материал

1. Создать `docs/<раздел>/<страница>.md`. Одна тема на файл, не надо пытаться
   уместить всё в одну страницу.
2. Рядом создать `docs/<раздел>/<страница>.ru.md`. Плагин i18n сопоставляет файлы
   по имени, дополнительная настройка не нужна.
3. Добавить английскую страницу в `nav` в `mkdocs.yml`. Файл вне `nav` соберётся,
   но в боковом меню его не будет.
4. Если заголовок новый, дописать его в `nav_translations` в блоке `locale: ru`.
5. Формулы писать в TeX: `$...$` в строке, `$$...$$` отдельным блоком.
   Диаграммы оформляются блоком ` ```mermaid `.
6. Ссылки между страницами делать относительными путями к `.md`-файлам, в обеих
   версиях. Сборка с `--strict` покажет битую ссылку.
7. Не переопределять символы заново. Таблица обозначений одна, в
   `docs/overview/notation.md`, остальные страницы ссылаются на неё.

Если перевод ещё не готов, сборка подставит английскую страницу в русское меню,
так что раздел не развалится, пока вы дописываете.

## Локальный просмотр

Нужен Python 3.10 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
mkdocs serve
```

Английская версия на <http://127.0.0.1:8000/lm-docs/>, русская на
<http://127.0.0.1:8000/lm-docs/ru/>. Префикс `/lm-docs/` берётся из `site_url`,
потому что репозиторий публикуется как проектный сайт GitHub Pages. Перед пушем
стоит прогнать `mkdocs build --strict`: он падает на битых ссылках и на
страницах, которых нет в навигации.

KaTeX и Mermaid лежат локально в `docs/assets/`, поэтому формулы и диаграммы
рендерятся без интернета.

## Соглашения

- В тексте и таблицах десятичные точки (`3.86806307`, `1.2661%`), чтобы числа
  можно было копировать в код без правок.
- У каждой метрики указана процедура измерения. Offline accuracy, runtime
  acceptance и decode speed остаются тремя разными числами, в друг друга они не
  переводятся.
- Гипотезы так и называются гипотезами, а не результатами.
- Русский первоисточник лежит в `original/` и задним числом не правится.

## Проверка сборки

```bash
mkdocs build --strict
```

Сборка должна проходить без предупреждений. `--strict` ловит битые ссылки и
страницы, выпавшие из навигации.
